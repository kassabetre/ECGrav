# ECGrav 1.17.0 — the source terms move into the package

P2's Hamiltonian couples to three operators — Euler characteristic, triangle count and
boundary-edge count — and until now all three lived in a working notebook, along with the
homogeneous `c·O` form that lets a driver temper in temperature and field at once. That made every
run's Hamiltonian depend on globals captured from the surrounding session, and it meant none of it
was under test.

This release moves all of it into the package, with the physical couplings as arguments and every
incremental delta checked against a full recount.

---

## ⚠️ Read before upgrading

**Nothing breaks.** Ten new public symbols; no existing symbol changes behaviour and no number
moves anywhere. Requires Wolfram Language 15.0+, unchanged.

If you have been driving runs from notebook definitions of `numTriangles`, `numBdryEdges`,
`delEulerChi` and friends, the package versions are **numerically identical** to them — see
*Verified* below. Existing results stay comparable.

## The three source operators

| | operator | delta | cost of the delta |
| --- | --- | --- | --- |
| triangles | `NumTriangles` | `delNumTriangles` | O(n), flat in density |
| boundary edges | `NumBdryEdges` | `delNumBdryEdges` | local to the common neighbourhood |
| Euler characteristic | `EulerChi` (existing) | `delEulerChi` | grows with the common neighbourhood |

`NumTriangles[Am]` counts 3-cliques, equivalently the 2-faces of the clique complex, as
$\mathrm{Total}[A \circ A^2]/6$. That is $\mathrm{Tr}[A^3]/6$ with one matrix multiply saved,
$A^2$ being symmetric. `HWeightedFaceCounts` cannot serve here: it builds every maximal clique and
caps its face count at size 5.

`delNumTriangles[Am,a,b]` is the signed count of common neighbours, $\pm(A^2)_{ab}$ — O(n) against
O(n³) for a recount. It does **not** read `Am[[a,b]]`, because the $c=a$ and $c=b$ terms of the dot
product carry the zero diagonal. That matters: the driver evaluates `delH` *before* deciding
whether to accept, so the delta must come off the current matrix without forming the toggled one.

**`NumBdryEdges` counts edges lying in exactly one triangle.** An edge in *no* triangle is not a
boundary edge, so `NumBdryEdges[Am] == 0` does **not** imply a closed combinatorial manifold — a
graph of loose edges scores zero. The octahedron and a 6-cycle both return 0, for opposite reasons,
and there is now a test pinning each.

`delEulerChi[Am,i,j]` is the alternating clique sum in closed form. Adding $\{i,j\}$ creates one new
clique per clique $S$ of the common neighbourhood $W = N(i) \cap N(j)$, namely $S \cup \{i,j\}$;
a clique of size $k$ comes from an $S$ of size $k-2$, so with $\chi = f_1 - f_2 + f_3 - \cdots$,

$$\delta\chi \;=\; \sum_{m \ge 0} (-1)^{m+1} c_m(W) \;=\; \pm\bigl(\chi(W) - 1\bigr),$$

the $-1$ being the empty clique's contribution. Only $W$ is enumerated, never the whole graph.

### A cost to plan around

`delEulerChi` is the expensive one and its cost grows with $|W|$, which is largest exactly in the
dense phase. Measured at $n = 21$:

| edge density | $\lvert W\rvert$ | `delEulerChi` | recomputing $\chi$ | saving |
| --- | --- | --- | --- | --- |
| 0.2 | 2 | 24.4 µs | 357 µs | 15× |
| 0.4 | 4 | 35.4 µs | 595 µs | 17× |
| 0.6 | 7 | 73.7 µs | 1378 µs | 19× |
| 0.8 | 14 | 261.3 µs | 1563 µs | 6× |

So the delta is doing its job — but the saving *shrinks* with density, because $|W| \to n-2$ and the
"local" enumeration approaches the global one. At density 0.8 it is already 59% of a full `delH`,
against 1.6 µs for `delNumTriangles`. Benchmark before fixing a phase-map grid.

## The homogeneous pair

`HHomogeneousSource[Am, e0, gChi, gBdry, c0, c1]` $= c_0 O_0 + c_1 O_1$, with
$O_0 =$ `HSourceTerms[Am, e0, gChi, gBdry]` $=$ `H2dCombManifold[Am,e0]` $+\, g_\chi \chi +
g_\partial\,\text{bdry}$, and $O_1 =$ `NumTriangles[Am]`. Run a driver at `bt = 1` and let the
couplings carry the temperature:

$$\beta\,(O_0 + n_{t0} O_1) \;=\; c_0 O_0 + c_1 O_1, \qquad c = \{\beta,\ \beta n_{t0}\}.$$

`HomogeneousCouplings[beta, nt0]` builds that $c$, `PhysicalCouplings` inverts it, and
`HomogeneousCouplingTable[betas, nt0s]` lays out the external-field table in the row order the
drivers index.

Two changes from the notebook form, both deliberate:

- **The physical couplings are arguments, not globals.** A run whose Hamiltonian cannot be
  reconstructed from its own record is a run that cannot be checked later.
- **Every numeric slot is gated on `NumericQ`, not `_Real`.** An integer-valued coupling does not
  match `_Real`; the call then returns *unevaluated*, and the acceptance test's deliberate fourth
  branch reads an undetermined comparison as **reject** — so the chain stops moving silently
  instead of erroring. Three tests pin integer couplings.

`HomogeneousConjugateObs[e0, gChi, gBdry]` returns the conjugate observables $\{O_0, O_1\}$ as a
list of pure functions. Prefer it to hand-writing that list: one mistyped entry leaves an
observable non-numeric, `MBARWeightBasis` forms `obs . Transpose[fields]` on it, and the whole MBAR
grid goes symbolic — with no error, just a run that never finishes.

### Using it with an external-field driver

The external-field drivers discard `hparams` and call `Apply[hamiltonian, externalFieldTable[[i]]]`,
so the head they receive must already carry the fixed couplings. Define it in your own context —
a head built inside the package would be a `Module` symbol in `` ECGrav`Private` ``, which
`DistributeDefinitions` skips silently, so the parallel subkernels would never receive it:

```wl
hHom[am_List, c0_?NumericQ, c1_?NumericQ] :=
    ECGrav`HHomogeneousSource[am, 3.0, -0.5, 0.5, c0, c1];
dHHom[am_List, c0_?NumericQ, c1_?NumericQ, i_Integer, j_Integer] :=
    ECGrav`delHHomogeneousSource[am, 3.0, -0.5, 0.5, c0, c1, i, j];
conjObsHom = ECGrav`HomogeneousConjugateObs[3.0, -0.5, 0.5];
```

`HHomogeneousSource` is directly usable by the single-parameter drivers, which do pass `hparams`.

## Verified

Nothing here was trusted from its derivation.

- **Agreement with the notebook definitions.** Over 105 graphs spanning $n = 4\ldots10$ and edge
  density $0.15\ldots0.9$, every edge slot, 2415 comparisons: `NumTriangles` and `delNumTriangles`
  are *exactly* equal to the notebook forms, and `numBdryEdges`, `delnumBdryEdges` and
  `delEulerChi` reproduce theirs. **Existing simulation results are unaffected.**
- **Every delta against a full recount, on every edge slot** — not a sampled one. A delta that is
  right on most slots and wrong on a few would surface only as a slowly wrong distribution.
- **`NumBdryEdges` against an independent oracle** that enumerates 3-cliques and counts edges in
  exactly one, sharing no code with the `Unitize` formulation.
- **The homogeneous identity** of `HomogeneousHamiltonian.md` §5, re-run against the package: over
  300 (graph, β, $n_{t0}$) comparisons the energy identity holds to $1.1\times10^{-13}$ and the
  delta identity to $2.8\times10^{-14}$ — the latter matching the figure the specification recorded.
- **Both degenerate paths of `delEulerChi`**, which go through `EulerChi[{}] == 0` and
  `EulerChi[{{0}}] == 1`, are pinned by their own tests; either is easy to break without noticing.

Suite **250 → 293 tests**, all green.
