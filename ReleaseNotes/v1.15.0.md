# ECGrav 1.15.0 — the density of the energy, as a function of β

`ConstrainedProbConjugateField` has reweighted a run to a target **external field** at fixed β
since it was written, returning the density of the conjugate variable there. This release adds the
other axis: a **beta-only** form that returns the density of the **energy** at a target inverse
temperature, so `P(β, E)` can be plotted against β from an ordinary beta-only parallel tempering
run.

---

## ⚠️ Read before upgrading

**Nothing breaks.** This release is purely additive. The existing four-argument
`ConstrainedProbConjugateField` is untouched — same signature, same return shape, same plot
range — and no numbers change anywhere in the package.

Requires Wolfram Language 15.0+, unchanged.

---

## The new form

```wl
ConstrainedProbConjugateField[targetBetas_List,      minusBetaF, energyMeasurements]
ConstrainedProbConjugateField[targetBeta_?NumericQ,  minusBetaF, energyMeasurements]
```

Both inputs come straight off a run — energy is chart column 3 in both the pre- and post-1.13.0
beta layouts, and it is the only column the package itself reads out of a beta chart:

```wl
en  = res[[2]][[All, All, 3]];
mbf = ComputeMinusBetaTimesFreeEnergy[en];

{dists, lo, hi, ess} = ConstrainedProbConjugateField[Subdivide[0.1, 5.0, 60], mbf, en];
```

The return is a `SmoothKernelDistribution` per target β, **one plot range shared across every
target**, and the MBAR **effective sample size** at each. The shared range is what makes a stack of
densities, or a `DensityPlot` of `P(E; β)`, coherent; the ESS is what tells you where the
reweighting has run out of support. The single-β form returns the same four with the distribution
and the ESS unwrapped.

Keys are bare inverse temperatures and values are flat energy lists — the shape a beta chart
already has, and the shape `ComputeMinusBetaTimesFreeEnergy` and `NegativeBetaTimesFreeEnergy`
already take. The argument order matches the latter.

## Why this is the same estimator

Beta tempering is the one-component homogeneous form of the external-field pattern. Writing the
hamiltonian as `H = c.O` with `c = {β}` and `O = {E}`, the Boltzmann exponent `β E` is exactly the
`c.O` that form reweights on:

| homogeneous form | beta-only run |
| --- | --- |
| `betaFixed` | `1.0` |
| field key | rung inverse temperature `β_j` |
| conjugate observable | energy `E_s` |
| target field | target inverse temperature `β_T` |

So the rung betas stand in for the external fields and the energy stands in for the conjugate
field. The mapping is new; the mathematics is not. `BetaSurfaceData` in `TemperingPlots.wls` rests
on the same identity.

## Two deliberate departures

**It is built on `MBARWeightBasis`, not on the four-argument pattern's nested `Sum`.** The MBAR
denominator carries no target, so it is formed once and reused at every β while only the numerator
moves — which is what makes a sweep over β, the reason the form exists, cheap. The helpers needed
no adaptation: they already coerce bare-real keys and scalar measurements to matrices.

**It computes its own plot range.** The four-argument form widens by `0.8*Min` and `1.2*Max`, then
runs two sign-fixing passes whose second reads the minimum the first has already overwritten. Those
factors widen an interval only for positive data. Energies are negative, so they shrink it and the
sign fixes then invert it — on a real run with energies in `{-60., -2.}`:

| step | min | max |
| --- | --- | --- |
| after `0.8*Min` / `1.2*Max` | −48.0 | −2.4 |
| after the two sign fixes | 0.48 | −0.096 |

leaving `min > max` with neither bound near the data. The beta form pads by a fraction of the
**span** instead, which is sign-agnostic. **The external-field form is unchanged**, so nothing that
depends on its ranges moves.

## What it refuses

Each of these would otherwise fail far downstream, as a symbolic expression or an error at plot
time rather than at the call:

| condition | message |
| --- | --- |
| `minusBetaF` and the measurements disagree on keys | `::keys` |
| measurements carry more than one component | `::notbeta` |
| every measurement list empty | `::nosamples` |
| every energy identical — a point mass, not a density | `::degenerate` |

The component check runs **before** `MBARWeightBasis`, because that helper forms
`obs.Transpose[fields]` itself: a wrong width raises `Dot::dotsh` inside it and hands back a
symbolic basis, at which point the width can no longer be read off it.

## Verified

| check | result |
| --- | --- |
| pointwise identical to the four-argument form on the same data expressed both ways | `< 1e-12`; means agreed to `0.` on one fixture |
| weights against the old nested-`Sum` formula, normalised | `2.6e-18` |
| `<E>` against `−d(−βF)/dβ`, differenced from `NegativeBetaTimesFreeEnergy` | `4.4e-7` at `ε = 1e-4` |
| reweighting to a sampled rung reproduces its sample mean | −59.04 against −58.92, the gap being kernel smoothing |
| returned range ordered and containing the data; PDF integrates over it | `1.0000000000000009` |
| list form against mapping the scalar form | ESS and range identical, PDF difference `0.` |
| ESS inside the ladder exceeds ESS far outside it | asserted, so the ESS cannot be a constant |

Two tests, suite **245 → 247 green**. Each fix was confirmed by reverting it *separately* — moving
the component check after the basis build, and restoring the four-argument range heuristic — each
independently failing `ConstrainedProbConjugateField-beta-form-range-and-guards`.

## Also in this release

`TemperingMixing.wls`, the mixing diagnostic that lives outside the paclet, gets two fixes:

- **`TrajectoryPlot[mix, j]` bounds-checks `j`.** Out of range used to fail three lines
  downstream: `perSweep[[j]]` raises `Part::partw` and stays *unevaluated*, so mapping over it maps
  over the index itself and `Missing[KeyAbsent, j]` surfaces as `Part::pkspec1` and
  `ListLinePlot::lpn`, never naming the argument that was wrong. It now says so and returns
  `$Failed`.
- **`MixingReport` reports the correlation-time fields in rung order**, as `corrTByRung` and
  `corrTMeasuredByRung`, alongside `flowByRung`. They previously came off the replicas in slot
  order, so reading `corrT[[k]]` against `flowByRung[[k]]` described a different rung — the two
  coincide only when the caller passed an ascending `btTable`. `mix["corrT"]` is unchanged and
  stays in slot order.
