# ECGrav 1.14.1 — Betti numbers no longer need the network

A patch release. **No value that any working call returned has changed.**

`CountHoles` wrapped `ResourceFunction["BettiNumbers"]`, which was the only network
dependency anywhere in the package. That resource became unfetchable, and the failure mode
was the bad kind: `CountHoles` raised nothing and returned `$Failed` wrapped around its own
argument —

```wl
CountHoles[tetrahedronBoundary]
(* $Failed[{Simplex[{1, 2, 3}], Simplex[{1, 2, 4}], Simplex[{1, 3, 4}], Simplex[{2, 3, 4}]}] *)
```

— so nothing failed at the call site and the nonsense only surfaced further downstream. This
hit **anyone without Wolfram Cloud access**, not merely CI, and Betti numbers are one of the
observables the package exists to report.

## What changed

Betti numbers are now computed from the boundary matrices of the complex,

$$b_k \;=\; \dim C_k \;-\; \mathrm{rank}\,\partial_k \;-\; \mathrm{rank}\,\partial_{k+1},$$

rational and unreduced — which is exactly what the resource returned. The public API is
unchanged: `CountHoles[c]` still gives the whole Betti vector and `CountHoles[c, k]` still
gives `b_k` with `k` counted from 0.

**Verified against the resource itself**, while it still resolves on a developer machine: the
suite's fixtures (the tetrahedron and octahedron boundaries, the torus, the Klein bottle, a
1-complex circle, two disjoint triangles, a single facet) and **120 random complexes across
p = 2…4 — 0 mismatches**. Cost is unchanged: 0.029 s against the resource's 0.028 s at
p = 5, M = 40.

The package now requires no network access for anything.

## Also

`Tests/ci-run.wls` now names the tests that failed rather than only counting them, and
mirrors that summary into GitHub Actions annotations. The job-log API needs push access, so
a red build could not previously be diagnosed without opening the web UI; annotations are
readable without authentication. It also prints an environment preflight — Wolfram version,
processor count, what `LaunchKernels` returns.

That tooling is what found this bug. The annotations from the failing run reported 15 red
tests, every one of them a `CountHoles` test, every one carrying
`ResourceObject::notfname` — which named the cause outright.

## Upgrading

Nothing to do. If you installed 1.14.0 and `CountHoles` returned something beginning
`$Failed[...]`, this release is the fix.

Requires Wolfram Language 15.0+, unchanged.
