# ECGrav 1.9.1 — three quantities that left the range a machine number can hold

`EulerChi[{}]` returned `$Failed` instead of 0. The Metropolis acceptance test flooded high-beta
runs with `General::munfl`. And `SGradDescent`'s softmax normalized to `Indeterminate` when every
move was uphill, at which point `RandomChoice` refused it outright.

Bug fixes only. **No public function was removed, no argument order changed, no new setting**, and
no result that previously computed changes value. Requires Wolfram Language 15.0+, unchanged.

---

## ⚠️ Read before upgrading

**If you write energy callbacks that take the link of an edge, the first fix affects you.** That
slice — the induced subgraph on the common neighbourhood of two vertices — is `{}` whenever the
two share no neighbour, and on a sparse graph that is most pairs: on 12 vertices with 18 edges,
32 of the 66.

The failure was loud rather than silent, so there is no quietly-wrong past result to distrust on
that account. But it surfaces a long way from its cause: the bad value propagates into whatever
arithmetic consumed it, and a driver will go on to do Metropolis with a non-numeric energy delta.

**The acceptance-test change alters no decisions.** `Exp[-beta*dE]` underflowing to `0.` already
rejected, which is the right answer; what it cost was speed and noise. Runs that completed before
will produce the same numbers.

**The `SGradDescent` fix does change outcomes — but only where the old code produced none.** An
all-uphill weight table used to fail rather than choose. Where it worked, the distribution is
unchanged to 7.8e-16.

## 1. The empty complex now has an Euler characteristic of 0

`EulerChi` dispatches on three patterns, two of which gate on `Depth`:

```wl
EulerChi[facetsLst_List /; (Depth[facetsLst] == 3 && Max[facetsLst] > 1)]
EulerChi[Amat_List     /; (Depth[Amat] == 3 && Max[Amat] <= 1)]
EulerChi[g_Graph]
```

`Depth[{}]` is 2, so the empty list matched none of them and fell to the catch-all. The irony is
that the convention was already implemented: `EulerChiAM`, which the adjacency overload delegates
to, opens with `If[n == 0, 0, ...]`. Nothing could reach it.

It arrives through the link of an edge:

```wl
sphInt = Flatten[Position[am[[i]]*am[[j]], 1]];   (* common neighbours of i and j *)
s*(EulerChi[am[[sphInt, sphInt]]] - 1)            (* -1 + $Failed when sphInt is {} *)
```

Two things let this through in a reported `GraphCTLSchedule` run: a spot check on one pair passed,
because whether that particular pair has a common neighbour is close to a coin flip; and the
`DelHUsableQ` gate passed, because it probes `dH[seed, 1, 2]` — one pair, on the seed graph.
Neither can see a failure that depends on which pair and which state.

Fixed by matching the literal, so the three existing overloads are untouched. `EulerChi::argerr`
also named only the facet-list form while the function accepts three; it now names all of them.

## 2. The Metropolis acceptance test is compared in log space

All 17 acceptance sites now evaluate `Log[u] < -beta*dE` rather than `u < Exp[-beta*dE]`. `Log` is
monotonic, so the two decide identically — but the exponential is not representable across much of
this model's range. At beta 7.5 a single edge toggle on a 12-vertex graph reaches `beta*dE` of
2340, mean 1570, against a threshold near 709. A run at beta 20 emitted 55 underflow messages;
the log form emits none.

This was never a correctness problem. `Exp[-775.]` returns exactly `0.`, so the comparison
rejected, which is right. What it cost was about **19x** on those calls — and the penalty tracks
the *result* leaving the normalized range, not the size of the argument:

| `Exp[x]` | time / 10⁶ | result |
| --- | --- | --- |
| `x = -700` | 0.069 s | 9.86e-305, normal |
| `x = -730` | 1.361 s | 9.2e-318, **subnormal** |

A double carries 11 exponent bits (~10^±308) and 53 mantissa bits. `e^-775` needs an exponent of
10⁻³³⁷ and is unrepresentable; `775.0` is an ordinary double. All the information is already in
`beta*dE` — exponentiating is what pushes it out of range, and log space simply never takes that
step. The replica swaps gain at the other end too: their argument is positive on a favourable
swap, where `Exp` was leaving machine arithmetic for arbitrary precision.

Three details this depended on, none of them a search-and-replace:

- `selectionProb` in the unlabeled path is an exact `Integer`/`Rational` ratio of automorphism
  group orders, so it is numericized before the `Log` — and the **product** underflowed in its own
  right when that ratio is below 1, so clamping `Exp` alone would not have sufficed.
- The acceptance `If` has **three** branches; the fourth fires when the comparison is undetermined
  and means reject. That is what silently swallowed the `$Failed` from fix 1, and it is preserved.
- `SimulatedAnnealing` looked immune behind `SetPrecision` and was not. `N[machineReal, p]` cannot
  *add* precision — only `SetPrecision` fabricates digits — so its `delE` stayed at machine
  precision and `arbitrary*machine` collapsed back to machine.

## 3. `SGradDescent`'s softmax is shifted by its maximum

The edge to flip is drawn with probability proportional to `Exp[-beta*deltaE]`. When every move is
uphill, every weight underflowed to `0.`, `Total` came out `0.`, and `w/Total[w]` made every entry
`Indeterminate` — `RandomChoice` then failed outright. On a complete graph at beta 200 the old
code raised ten distinct message types (`General::munfl`, `Power::infy`, `RandomChoice::wghtv`,
`Part::partw` among them) and returned through a cascade of errors.

Note the sign runs the opposite way from the acceptance test: the exponent is `-beta*deltaE`, so
it is the **downhill** edges — the ones softmax exists to favour — that made it large and positive
and pushed `Exp` into arbitrary precision at the other end. Both ends bit.

Subtracting the maximum cancels exactly from numerator and denominator, so the distribution is
untouched while the largest weight becomes `Exp[0] == 1` and `Total` can never be 0. Where the old
form gave three `Indeterminate`s, the new one recovers the distribution those weights actually
have — `1 : 1.9*^-98 : 2.7*^-261`.

## How this was verified

- **The link-of-an-edge identity**: toggling edge `(i,j)` changes chi by `chi(link) - 1`. Across 40
  random 8-vertex graphs — **1120 toggled pairs, 302 with an empty link** — that agrees with
  recomputing `chi(new) - chi(old)` in every case.
- **The acceptance rewrite**: **34.5M** plain comparisons and **220k** spanning realistic
  automorphism ratios, with **zero** disagreements; and end-to-end against the previous code at
  beta 7.5 and 20, both labelings, giving identical energies, magnetizations and edge counts while
  underflow messages went from 55 to 0.
- **The softmax**: 20,000 well-conditioned tables agree with the naive form to **7.8e-16**.
- Every new test was run against the unfixed code, where it fails.

The suite is at **188 tests**, all passing.
