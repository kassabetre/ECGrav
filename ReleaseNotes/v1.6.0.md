# ECGrav 1.6.0 — fully unlabeled pure complexes

This release completes the trio of labellings for pure simplicial complexes, and makes the
unlabeled random generator exact instead of rejection-based — up to **14,000× faster**.

A pure complex can be counted three ways depending on what carries a label. ECGrav had two of
them; this adds the third, which is the one that counts **isomorphism classes**:

| function | vertices | facets | counts |
| --- | --- | --- | --- |
| `NumVertexLabeledPureComplexes` | labelled | unlabelled | labelled facet sets |
| `NumFacetLabeledPureComplexes` | unlabelled | labelled | separating incidence tableaux |
| **`NumUnlabeledPureComplexes`** *(new)* | unlabelled | unlabelled | **isomorphism classes** |

---

## ⚠️ One reproducibility change

`RandomUniformUnlabeledPureSimplicialComplex` returns a **different complex for a given
`SeedRandom`** than it did in 1.5.0. The distribution is unchanged — still exactly uniform over
isomorphism classes — but the algorithm is completely different, so seeded sequences do not carry
across the version.

If you have results that depend on a specific seeded draw from this generator, pin ECGrav 1.5.0
for those, or regenerate. Nothing else in the package is affected: no function was removed, no
argument order changed, and every other value is bit-for-bit what it was.

---

## New — `NumUnlabeledPureComplexes[p, M, n]`

The number of pure complexes with `M` facets of `p` vertices each, on `n` vertices, counted up to
relabelling the vertices *and* permuting the facets. `NumUnlabeledPureComplexes[p, M]` sums over
the vertex count. Argument order matches its two siblings: purity, facet order, vertex count.

```wolfram
NumUnlabeledPureComplexes[3, 4, 6]
(* 15 *)

{NumVertexLabeledPureComplexes[2, 3, 4],
 NumFacetLabeledPureComplexes[2, 3, 4],
 NumUnlabeledPureComplexes[2, 3, 4]}
(* {16, 4, 2}  -- 16 labelled complexes, but only two classes: the path and the star *)
```

At `p = 2` these are the unlabelled graphs with no isolated vertex, which gives a check against
something entirely outside the package: summed over `M`, the values reproduce the differenced
unlabelled-graph sequence (OEIS A000088) out to `n = 13`.

Cost grows like `PartitionsP[n]`, so `n` — not `p` or `M` — is the limiting argument. Roughly 1 s
at `n = 25`, 3 s at `n = 30`. Large facet orders are cheap: `{3, 100, 12}` returns a 56-digit
value in under a tenth of a second.

## Changed — the unlabeled sampler is now exact and rejection-free

`RandomUniformUnlabeledPureSimplicialComplex` previously drew from the vertex-labeled generator
and accepted with probability `|Aut|/n!`. That is correct, but the acceptance rate collapses
factorially with the vertex count. It now samples a fixed pair of the symmetric-group action
directly, where every isomorphism class contributes exactly `n!` such pairs whatever its size.

| `{p, M, n}` | 1.5.0 | 1.6.0 | |
| --- | --- | --- | --- |
| `{2, 3, 4}` | 3.7 ms | 0.12 ms | 31× |
| `{3, 4, 6}` | 146 ms | 0.32 ms | 458× |
| `{3, 4, 8}` | 3.31 s | 0.68 ms | 4,800× |
| `{3, 4, 10}` | **11.4 s** | **0.82 ms** | **14,000×** |

Per sample, warm. Parameter ranges that were simply out of reach before are now routine.

With the vertex count free, `{p, M}` now draws `n` from `NumUnlabeledPureComplexes` directly;
previously it drew from the vertex-labeled counts and let rejection repair the difference.

## Uniformity is proved, not just tested

The sampler's correctness rests on three exact identities rather than on goodness-of-fit: the
cycle-type weights sum to `n! × NumUnlabeledPureComplexes[p,M,n]`, the size-profile marginals sum
to the per-cycle-type covering count, and that count at the identity cycle type reproduces
`NumVertexLabeledPureComplexes`. Together these force the probability of every isomorphism class
to be exactly `1/U` — which was then computed directly rather than sampled, and came out exactly
`1/U` for every class on seven parameter sets.

The count itself is verified three independent ways: against a brute-force oracle that enumerates
and canonicalises 29 parameter sets, against a Burnside average built from explicitly enumerated
fixed sets, and against the external unlabelled-graph sequence above.

## Documentation

Two new top-level specifications sit alongside `Theory.md`, both code-grounded:

- **[`UnlabeledCount.md`](https://github.com/kassabetre/ECGrav/blob/main/UnlabeledCount.md)** —
  the counting algorithm: the derivation, the worked example, cost, and what was ruled out
  (there is no recurrence of the kind the vertex-labeled count has, and the document explains
  why).
- **[`UnlabeledSampler.md`](https://github.com/kassabetre/ECGrav/blob/main/UnlabeledSampler.md)** —
  the sampler: the pair-sampling principle, the five steps, and the exactness lemma that had to
  be corrected rather than carried over from the facet-labeled case.

`NumUnlabeledPureComplexes` has a reference page in the built documentation, and the API guide
lists all three counts.

## Installation

Download `ECGrav-1.6.0.paclet` from the assets below, then:

```wolfram
PacletInstall["/path/to/ECGrav-1.6.0.paclet"];
Needs["ECGrav`"];
```

Or load the source directly, with no build step:

```wolfram
PacletDirectoryLoad["/path/to/ECGrav"];
Needs["ECGrav`"];
```

Requires Wolfram Language 14.2+.
