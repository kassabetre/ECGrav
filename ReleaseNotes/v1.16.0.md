# ECGrav 1.16.0 — the energy is a lattice, and the density estimator should say so

1.15.0 added `P(β, E)` from a beta-only tempering run. Plotting one at a cold target shows a row
of sharp spikes rather than a curve. That is not a reweighting error — it is the kernel density
estimate resolving individual **energy levels**, because the energy of a graph Hamiltonian is
lattice-valued and the automatic bandwidth falls below the level spacing.

This release makes that visible, overridable, and avoidable.

---

## ⚠️ Read before upgrading

**Nothing breaks.** The default path is untouched and no numbers change. The only new output on an
existing call is a warning, in exactly the situation where the previous result was misleading.

Requires Wolfram Language 15.0+, unchanged.

---

## The problem, stated precisely

A kernel density estimate places a bump of width $h$ — the **bandwidth** — on every sample and adds
them up, each scaled by its weight. Whether the result reads as a curve or as a comb is decided by
$h$ against $\Delta$, the spacing between attainable energies:

$$h \gtrsim \Delta \;\Rightarrow\; \text{adjacent bumps overlap and merge};\qquad
h \ll \Delta \;\Rightarrow\; \text{one separated bump per occupied level}.$$

`SmoothKernelDistribution` chooses $h$ by Silverman's rule on the weighted sample, roughly
$1.06\,\sigma_w\,\mathrm{ESS}^{-1/5}$. That rule was derived for continuous data and has no notion
of a lattice — and $\sigma_w$ **collapses as the target gets colder**, because the reweighted
energy distribution narrows onto fewer levels. Measured on a run with $\Delta = 1$:

| $\beta_T$ | ESS | levels carrying $>0.1\%$ | $\sigma_w/\Delta$ | $h$ | $h/\Delta$ |
| --- | --- | --- | --- | --- | --- |
| 0.05 | 151 | 71 | 19.8 | 3.57 | 3.6 |
| 0.15 | 271 | 72 | 23.1 | 4.24 | 4.2 |
| 0.35 | 1247 | 7 | 7.9 | 1.46 | 1.5 |
| 0.6 | 2254 | 2 | 1.83 | 0.50 | **0.5** |
| 1.0 | 2168 | 1 | 0.17 | 0.50 | **0.5** |

Counting local maxima over a fixed window shows it directly: $h=0.5$ gives 12 bumps, $h=1.0$ gives
5, $h=1.5$ gives 1, $h=2.0$ none.

**Rescaling the observable does not help.** Silverman's rule is scale-invariant: divide the energy
by any constant and $h$, $\sigma_w$ and $\Delta$ all shrink together, leaving $h/\Delta$ exactly
where it was. What matters is how many lattice levels the *reweighted* distribution spans, which is
a property of the target, not of the units.

## What is new

```wl
{dists, lo, hi, ess} = ConstrainedProbConjugateField[4.0, mbf, en, "Bandwidth" -> 1.0];
{pmf,   lo, hi, ess} = ConstrainedProbConjugateField[4.0, mbf, en, "Form" -> "PMF"];
```

| option | values |
| --- | --- |
| `"Bandwidth"` | `Automatic` (default, unchanged) or anything `SmoothKernelDistribution` accepts |
| `"Form"` | `"Density"` (default) or `"PMF"` |

**`"Bandwidth"`** overrides the automatic choice. Between $\Delta$ and $2\Delta$ is usually right:
wide enough to bridge adjacent levels, narrow enough to keep genuine structure. Beyond a few
$\Delta$ real features start washing out.

**`ConstrainedProbConjugateField::lowbandwidth`** reports the bandwidth actually used and the
spacing, so a first run without options tells you your own $\Delta$:

```
The kernel bandwidth 0.25 is below 0.5, the spacing between attainable energies, so the
density resolves individual energy levels instead of smoothing across them. Set
"Bandwidth" -> 0.5 or larger, or use "Form" -> "PMF" for the exact per-level probabilities.
```

It is raised **once per call**, naming the narrowest bandwidth in the sweep — sixty targets would
otherwise emit sixty copies and then be cut off by `General::stop`.

**`"Form" -> "PMF"`** skips the kernel estimate and returns, per target, a sorted `Association`
`<|E -> p|>` of the exact reweighted probability of each attained energy. For a lattice-valued
energy that is the true object and the density only a way of drawing it. `lo`, `hi` and `ess` are
unchanged. Plot it as atoms — `PDF` of a discrete object is zero away from the levels:

```wl
ListPlot[Normal[pmf], Filling -> Axis, PlotRange -> All]
```

## How $\Delta$ is measured, and when the warning stays quiet

$\Delta$ is the smallest positive gap between distinct sample values. On a genuinely continuous
observable the closest pair out of thousands of samples is minute, so $h/\Delta$ is enormous and the
warning cannot misfire. Floating-point noise between two values meant to be equal shrinks $\Delta$
and *suppresses* the warning — a false negative, which is the safe direction. `"Form" -> "PMF"`
never warns, since no bandwidth is involved.

## Verified

| check | result |
| --- | --- |
| warning fires at a cold target | asserted |
| warning **silent** at a hot target | asserted — a warning hardwired either way fails |
| `"Bandwidth"` reaches the estimator | asserted behaviourally: a wider kernel gives strictly fewer local maxima |
| PMF sums to 1 | $<10^{-12}$ |
| PMF carries one atom per attained level | exact count |
| PMF reproduces the MBAR weighted mean | $<10^{-9}$ — it is the same weights merged, not smoothed |
| bad `"Form"` refused; options survive the scalar → list delegation | asserted |

One test, suite **247 → 248 green**. Each of the four behaviours was confirmed by reverting it
*separately* — disabling the warning, forcing it on unconditionally, ignoring `"Bandwidth"`, and
leaving the PMF unnormalised each independently fail the new test. Forcing the warning on also
breaks the other two `ConstrainedProbConjugateField` tests, which are silence checks by
construction.
